1. 典型 Bug 排查手册

1.1. 校验和错误

典型现象

  • Wireshark 抓到的 IP / UDP / TCP checksum 显示为 0。

  • 组件测试通过，但 udp_server / tcp_server 抓包结果异常。

  • 接收端始终把包丢弃，或者调试工具能发包但收不到回包。

优先排查

  1. 是否开启了硬件校验和卸载（Checksum Offload）。

  2. 计算校验和前，相关字段是否先清零。

  3. 参与计算的数据长度若为奇数，末尾是否补了一个 0 字节。

  4. TCP / UDP 是否正确使用了伪首部，且伪首部中的协议号、源 / 目的 IP 正确。

排查路径

  • 环境问题优先参考 环境配置检查清单 与 Lab7 常见问题（UDP）。

  • IP 校验和重点检查 Lab5：协议栈之IP协议实现 中 checksum16() 的实现。

  • UDP / TCP 校验和重点检查 Lab7：协议栈之UDP协议实现、Lab9：小型Web服务器的设计与实现 中 transport_checksum() 的实现与调用顺序。

1.2. TCP 序列号与确认号更新错误

典型现象

  • tcp_test 局部通过，但 tcp_server 无法建立连接。

  • 三次握手后立刻被对端重置，或者四次挥手停在中间状态。

  • HTTP 请求能发出，但浏览器迟迟等不到完整响应。

优先排查

  1. SYN 和 FIN 都各自占用一个序号。

  2. ACK 表示“下一个期望收到的字节序号”，不是“最后收到的字节序号”。

  3. 回复报文时，seq、ack、标志位、状态迁移是否同步更新。

  4. 发送纯 ACK 包、携带数据包、关闭连接包时，序列号递增规则是否一致。

排查路径

  • 对照 Lab9：小型Web服务器的设计与实现 中三次握手、四次挥手和状态机说明。

  • 抓包时按连接过程逐包对齐：先看 SYN / SYN|ACK / ACK，再看数据包，最后看 FIN / ACK。

1.3. ARP 表未更新导致反复广播

典型现象

  • 每次发包前都重新广播 ARP Request。

  • Wireshark 中能看到 ARP Response，但后续 IP 包仍发不出去。

  • Ping 或 UDP 测试中，ARP 包往返正常，但业务数据始终没有继续向下传。

优先排查

  1. 收到 ARP Request / Response 后，是否都正确更新了 ARP 表。

  2. 发送到异网主机时，ARP 查询的对象是否是下一跳网关，而不是最终目的主机。

  3. ARP 表的 key / value 是否按正确的 IP 和 MAC 填写。

  4. ARP 表项是否因为超时、覆盖或未命中而被反复丢弃。

排查路径

  • 对照 Lab3：协议栈之ARP协议实现 中 ARP 表与同网段 / 异网段解析流程。

  • 如果看到“ARP 正常、IP 不走”，优先核对 map_set() / map_get() 的调用时机与参数。

1.4. IP 分片偏移单位错误

典型现象

  • ip_frag_test 无法通过。

  • 分片数量看起来正确，但接收端重组失败。

  • Wireshark 中 fragment offset 明显不对，或者后续分片起始位置错位。

优先排查

  1. IP 分片偏移字段的单位是 8 字节，不是字节数本身。

  2. 除最后一个分片外，其余分片的数据长度都应是 8 的整数倍。

  3. MF 位只有最后一个分片为 0，其余分片都应为 1。

  4. 所有分片的 id 必须一致。

排查路径

  • 对照 Lab5：协议栈之IP协议实现 中 IP 分片示意图与分片步骤。

  • 先打印每个分片的 payload 长度、offset、MF，再和抓包结果逐项比对。

1.5. 协议字段填写错误

典型现象

  • 报文看起来发出去了，但上层根本收不到。

  • 接收路径落到了“协议不可达”或“端口不可达”分支。

  • Wireshark 能识别出 IP 包，但不能正确识别上层协议。

优先排查

  1. IP 首部中的 protocol 字段填写的是上层协议号，不是端口号。

  2. TCP / UDP 的源端口、目的端口要和应用层监听端口对应。

  3. 端口号、长度、校验和等 16 位字段要做网络字节序转换。

  4. EtherType、ARP opcode、IP protocol 等常量值不要混淆。

排查路径

  • 链路层问题先看 Lab2：协议栈之Eth协议实现。

  • IP 协议号问题重点看 Lab5：协议栈之IP协议实现。

  • UDP / TCP 端口问题重点看 Lab7：协议栈之UDP协议实现、Lab9：小型Web服务器的设计与实现。

1.6. 环境兼容性问题

典型现象

  • PacketSendPacket failed、no interface found、have the same ip with me。

  • Windows 下抓包正常，但调试工具就是收不到响应。

  • 无线网卡抓包结果长期异常，且无法关闭校验和卸载。

优先排查

  1. Windows 环境下 Npcap 是否使用课程建议版本 1.31。

  2. 安装时是否开启 WinPcap API-compatible Mode。

  3. 是否抓错网卡、写错 NET_IF_IP，或把协议栈 IP 配成了真实网卡 IP。

  4. 若只有无线网卡且无法关闭 Offload，是否应直接切到 纯 Linux/WSL2 环境配置（veth）。

排查路径

  • 环境优先参考 环境配置检查清单。

  • Windows / 无线网卡 / Npcap 相关问题继续看 Lab7 常见问题（UDP）。
