实验目的
=====================
1. 熟悉 TCP 头部结构及各字段功能。
2. 掌握 TCP 协议的序列号、确认应答、连接状态机等关键机制，理解三次 “握手” 和四次 “挥手” 过程。
3. 熟悉HTTP/1.1 协议的交互过程与格式。

实验任务
===========

本次实验包括以下两个子任务：

1. 在完成协议栈ICMP协议的基础上，实现仅支持服务端逻辑的简化版TCP协议。该实现包含序列号机制、确认应答机制、以及连接状态机，以实现面向连接的基础可靠传输功能。
2. 基于上述简化版 TCP 协议，构建一个小型Web服务器，使其能够处理并响应简单的HTTP请求。

最终构建的系统应支持基本的网页浏览功能，并且要通过实验评测系统的测试验证。

.. important::
   **常见坑点预警**

   - ``SYN`` 和 ``FIN`` 都各占用一个序号；不要只在“携带数据”时才更新 ``seq``。
   - ``ACK`` 表示“下一个期望收到的字节序号”，不是“最后收到的那个字节序号”。
   - TCP 校验和覆盖伪首部、TCP 头部和数据区；计算前同样要先把校验和字段清零。
   - ``tcp_test`` 通过并不代表 ``tcp_server`` 一定正确；三次握手、四次挥手和 HTTP 集成测试仍要抓包核对。
   - 若连接卡在握手 / 挥手中间状态，请优先参考 :doc:`/appendix-g/0bug-handbook` 中“TCP 序列号与确认号更新错误”。

实验原理
===========

TCP协议概要
~~~~~~~~~~~~~~

TCP（Transmission Control Protocol）协议是一种面向连接、可靠且基于字节流的传输层通信协议。与 UDP（User Datagram Protocol）不同，UDP 不保证数据传输的可靠性，而 TCP 通过一系列机制来实现可靠传输。具体而言，TCP 会先建立连接，利用序列号确保数据有序传输，借助确认应答机制保证接收方正确收到数据，同时通过超时重传机制修复可能丢失的数据。此外，TCP 还具备流量控制和拥塞控制机制，能够根据网络状况动态调节发送速率，避免网络过载。这些特性使得 TCP 特别适用于文件传输、电子邮件和网页浏览等对数据可靠性要求较高的通信场景。

在本次实验中，我们只需实现支持服务端逻辑的简化版 TCP 协议，重点关注连接的建立以及确认应答机制，从而实现基础的可靠传输能力。

TCP头部
-------------------

传输层位于网络层之上，其数据包结构如下图所示：

.. image:: TCP-1.png

TCP 的头部结构长度通常为 20 字节，若包含可变长的选项部分，最长可达 60 字节。

.. image:: TCP-2.png

1.  **源端口号（Source Port）**\ ：长度 16
    位。标识数据发送方的端口号，用于区分同一主机上多个应用程序或进程。
2.  **目的端口号（Destination Port）**\ ：长度 16
    位。标识数据接收方的端口号。与源端口号一起，用于确定传输数据的源应用和目标应用。
3.  **序号（Sequence Number）**\ ：长度 32
    位。表示数据包中第一个字节的序列号，用于数据有序传输和丢包重传。在连接建立时（SYN
    报文），该值为初始序列号（ISN）；在数据传输时，序号随着数据的传输按字节递增。
4.  **确认序号（Acknowledgment Number）**\ ：长度 32
    位。期望从对方接收数据的字节序号，累计确认，用于实现可靠数据传输。只有当
    ACK 位被置为 1
    时，该字段才有效。表示期望接收的下一个数据字节的序列号。
5.  **首部长度（Header Length/Data Offset）**\ ：长度 4 位。指示 TCP
    首部的长度，单位是 4
    字节。例如：首部长度为20字节，则该字段值为20/4=5。
6.  **保留（Reserved）**\ ：长度 3 位。保留字段，必须设置为 0。
7.  **标志位（Flags）**\ ：长度 9 位。用于标识 TCP
    报文段的状态和控制数据传输，本次实验主要关注以下几个标志位：

    -  **ACK**\ ：确认标志，标识确认序号字段有效。
    -  **RST**\ ：复位标志，用于异常中断、重新建立TCP连接。
    -  **SYN**\ ：表示该TCP段是一个建立新连接请求控制段。
    -  **FIN**\ ：表明请求释放TCP连接。

8.  **窗口大小（Window Size）**\ ：长度 16
    位。表示接收方的接收窗口大小（缓冲区剩余空间），用于流量控制，控制发送方的发送速率，避免网络拥塞。
9.  **校验和（Checksum）**\ ：长度 16
    位。用于差错检测，包括TCP伪首部、TCP首部和应用层数据三部分。
10. **紧急指针（Urgent Pointer）**\ ：长度 16 位。本实验默认置零。
11. **数据（Data）**\ ：可变长度。实际要传输的应用层数据。

TCP建立连接：三次“握手”
-------------------

TCP建立连接的过程如下所示：

1. 服务器最初处于 LISTEN（监听）状态，等待客户端的连接请求。
2. 客户端初始化序列号 seq = x，并向服务器发送 SYN 报文，该报文用于请求建立新连接。
3. 服务器收到SYN报文后进入SYN_RCVD状态，初始化服务端序列号seq=y，并向客户端回复SYN
   \| ACK报文，确认号ack_seq=x+1。
4. 客户端收到SYN \|
   ACK报文后，回复ACK报文，序列号seq=x+1，确认号ack_seq=y+1，报文可能携带数据。
5. 服务器收到ACK报文后，转移到ESTABLISHED状态，连接建立完成，进行数据传输。

.. image:: TCP-3.png

TCP断开连接：四次“挥手”
--------------------------------------

TCP断开连接的过程如下所示：

1. 服务器最初处于ESTABLISHED状态。
2. 客户端发送FIN报文，请求关闭连接。
3. 如果服务器没有还要传输的数据，则跳到步骤4；否则，回复ACK确认关闭请求，并进入CLOSE_WAIT状态。
4. 服务器发送FIN \|
   ACK报文给客户端，表明准备关闭连接，进入LAST_ACK状态。
5. 客户端收到FIN报文后，回复ACK确认。客户端会进入等待状态，等待2倍MSL（报文最大存活时间），确保所有报文被接收后，正式关闭连接。
6. 服务器收到ACK，连接关闭。

.. image:: TCP-4.png

实验框架简介
-------------------

TCP 连接对象
^^^^^^^^^^^^

实验框架可以串行地同时支持多个 TCP 连接。

TCP 连接的上下文信息通过 ``tcp_connection`` 结构体表示，定义于 ``tcp.h``
文件：

.. code:: c

   typedef struct tcp_connection {
       /* TCP connection states */
       tcp_state_t state;        // 当前 TCP 连接的状态（如 LISTEN、ESTABLISHED）
       uint8_t not_send_empty_ack; // 标识是否需要发送空 ACK
       /* TCP communication states */
       int port;                 // 连接对应的本地端口号
       uint32_t seq;             // 当前发送序列号
       uint32_t ack;             // 当前确认号
   } tcp_conn_t;

TCP 连接表 ``tcp_conn_table``
是一个哈希表（\ ``map_t``\ ），用于管理所有当前的 TCP 连接，定义于
``tcp.c`` 文件：

.. code:: c

   static map_t tcp_conn_table;  // [src_ip, src_port, dst_port] -> tcp_conn

其键为一个三元组（\ ``tcp_key_t`` ），由远端 IP
(``remote_ip``)、远端端口 (``remote_port``) 和本地端口 (``host_port``)
组成；值为对应的 TCP 连接对象 (``tcp_conn_t``)。

当接收到一个 TCP
数据包时，系统可以通过\ ``tcp_get_connection()``\ 函数查找或者新建对应的
TCP 连接；系统也可以通过\ ``tcp_close_connection()``\ 函数关闭特定的 TCP
连接。

简化与不足
^^^^^^^^^^

本实验仅实现了一个简易的用于服务端的TCP协议（runnable），包括如下基本功能：

1. **连接管理**：通过状态机实现服务端TCP连接的生命周期，包含“三握手”连接建立和“四挥手”连接释放。

   .. image:: TCP-5.png

2. **基础可靠传输**：实现了基本的序列号和确认号机制，实现了简单的包乱序处理，可以保证上层应用接收到的数据包有序。

不过，该简化版 TCP 协议存在以下剪枝和不足：

1. **流量控制/拥塞控制**：固定窗口大小不变（为最大大小）、未实现慢启动和拥塞避免等算法。
2. **可靠传输**：未实现超时重传、未对乱序包进行高效处理，故而仅适用于网络环境稳定的场景。
3. **未实现客户端逻辑**：仅支持服务端逻辑，无法作为客户端与其他服务器建立连接。

HTTP协议概要
~~~~~~~~~~~~~~~~~~~~~~~~

HTTP（HyperText Transfer
Protocol，超文本传输协议）是万维网应用层的通信协议，采用C/S架构，用于客户端与服务器之间的数据传输。客户端（如浏览器）通过发送HTTP请求获取服务器上的资源，服务器则返回网页、图片或视频等对象作为响应内容。HTTP基于TCP协议，依靠其可靠的传输机制保证数据的完整性和有序性。同时，HTTP是无状态的，每次请求都是独立的，不会保留之前的交互信息。

HTTP/1.0是最早的HTTP协议版本，每请求一个对象都会建立和关闭一次TCP连接，导致频繁的连接开销，效率较低。HTTP/1.1在此基础上进行了多项改进，最显著的变化是引入了持久连接（Persistent
Connection），默认开启\ ``Connection: keep-alive``\ ，允许在一个TCP连接上进行多次对象的请求和响应，显著减少了连接建立和释放的开销。HTTP/1.1是当前Web通信的主流协议。

在本次实验中，我们需要基于简易TCP协议实现一个小型的Web服务器，能够处理并响应简单的HTTP/1.1请求，实现基本的网页访问功能。

HTTP/1.1 交互过程
---------------------------

1. **HTTP服务器监听请求**\ ：HTTP服务器默认在80端口等待客户端的连接请求。
2. **建立TCP连接**\ ：HTTP客户端（如浏览器）向服务器发起连接请求，服务器接受请求后，双方通过三次握手建立TCP连接。
3. **客户端发送HTTP请求**\ ：客户端通过已建立的TCP连接发送HTTP请求，消息中的URL用于标识客户端请求的资源。请求过程通常如下：

   -  客户端首先请求index.html文件，该文件中可能包含对其他资源的引用。
   -  客户端根据这些引用，并行发起多个请求，获取页面中涉及的所有对象，如JPEG图片、视频文件、动态脚本等。

4. **服务器响应请求**\ ：服务器解析客户端的HTTP请求，生成包含所请求资源的HTTP响应消息，并通过TCP连接发送给客户端。
5. **关闭连接**\ ：当所有资源传输完成后，客户端主动关闭TCP连接（发送FIN报文），释放网络资源。

HTTP/1.1 协议格式
---------------------------

由上述交互过程可以看到，HTTP协议有两类消息：请求消息（request）和响应消息（response）。

请求消息
^^^^^^^^

.. code:: bash

   GET /somedir/page.html HTTP/1.1<CR><LF> # 请求行，包含GET、URL、协议版本
   Host: www.someschool.edu<CR><LF>        # 首部行（本实验不涉及）
   User-agent: Mozilla/4.0<CR><LF>
   Connection: close<CR><LF> 
   Accept-language:fr<CR><LF> 
   <CR><LF>
   (extra carriage return, line feed)      # 请求体（本实验不涉及）

..

   注：<CR>和<LF>分别指回车符（Carriage Return）和换行符（Line
   Feed），即\\r和\\n。

响应消息
^^^^^^^^

.. code:: bash

   HTTP/1.1 200 OK<CR><LF>         # 状态行(协议版本， 状态码，相应状态信息)
   Connection: Keep-Alive<CR><LF>  # HTTP/1.1 默认开启长连接
   Content-Type: text/html<CR><LF> # 响应体的MIME类型
   Content-Length: 6821<CR><LF>    # 响应体长度
   <CR><LF>                        # (注意此处需要有一个<CR><LF>)
   data data data data data ...    # 数据

其中，状态代码可以是“200 OK”、“404 NOT FOUND”等。

TCP数据报输出处理
--------------------------

同学们要自主实现 tcp_out() 函数，其具体功能和步骤如下：

**Step1** 添加 TCP 报头：

首先调用buf_add_header()函数添加TCP报头。

**Step2** 填充 TCP 首部字段：

将 win 字段设置为最大 TCP 窗口大小（TCP_MAX_WINDOW_SIZE），uptr 字段置为零。操作时需注意字节序问题。

**Step3** 计算并填充校验和：

先把校验和字段填充为 0，接着调用 transport_checksum() 函数计算校验和，最后将计算得到的校验和结果填入校验和字段。

**Step4** 发送 TCP 数据报：

调用 ip_out() 函数，将处理好的 TCP 数据报发送出去。

TCP数据报输入处理
--------------------------

同学们要自行实现 tcp_in() 函数中的状态转移和响应部分，具体功能及步骤如下：

**Step1** 更新连接状态与回复报文标志：

依据接收包的数据，更新当前 TCP 连接的内部状态，并填写回复报文的标志部分。

**Step2** 数据交付与错误处理：

如果接收报文携带数据，则将数据部分交付给上层应用。调用map_get()函数查询tcp_handler_table是否有该目的端口号对应的处理函数（回调函数）。如果没有找到，则调用buf_add_header()函数增加IPv4数据报头部，再调用icmp_unreachable()函数发送一个端口不可达的ICMP差错报文。如果能找到，则去掉TCP报头，调用处理函数来做相应处理。

**Step3** 发送回复报文并更新序列号：

调用 tcp_out() 函数发送回复报文，同时更新 TCP 连接的序列号。详细步骤可参考代码注释。
